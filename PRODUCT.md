# NovaClient website

Public English-language presentation and download site plus a Discord-authenticated player account. Playing requires no activation key. Players optionally prove a signed device service identity using a temporary Diagnostics code, then choose their primary nickname through the same linking routine as the Discord bot. Profiles show real client-recorded stats, effective license role and assigned custom title. Public leaderboards show recorded totals; these are not official KoG rankings. Preserve black/purple identity, reduced-motion support, official distribution links and existing feature truth. No activation keys, device proofs or private credentials are public.

All visible account and leaderboard pages are hosted by GitHub Pages under https://novaclient.tech/account/. Only API and OAuth callback run on the license server. OAuth returns a one-use 90-second exchange code in a fragment; the Pages frontend exchanges it over HTTPS for a server-limited website session in localStorage (shared across the site tabs). The current production session lifetime remains one hour; a longer lifetime requires a coordinated backend rollout and is not part of this site-only publication. CORS permits only the exact https://novaclient.tech origin. No session token is placed in a URL.

A single shared header is used by the landing, player account and leaderboard pages. Its account control reads authenticated identity without rotating form CSRF tokens; it displays the primary nickname and effective role when verified, and supports server-side logout.

Public ranking entries link to opaque player profile IDs. Public profiles expose only the displayed name, effective role, client-recorded stats, map attempts and the currently selected title; they never expose license numbers, Discord IDs or device proofs. Earned title names/colors are sourced from kog_stats_data.cpp, with effects from kog_stats.cpp. Custom titles must be enabled and assigned to the same license. The account page renders a title picker only when the API supplies allowed choices; the signed server command and client acknowledgement are a separate backend/client rollout and are not active from a site-only deployment. A selected value of -1 displays no title, rather than substituting an arbitrary assignment.
